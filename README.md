# 遊戲化國小英文練習

給一個班級用的英文單字練習遊戲。學生用班級代碼加暱稱進場，**不收真實姓名與 email**。

## 現在能跑什麼

```bash
npm install
npm run dev
```

打開之後：輸入班級代碼與暱稱 → 選關 → 玩守塔 → 看結算。
右上角的「老師」可以看全班最常錯的字，以及額外開放關卡。

## 架構

完整說明在 [`docs/architecture.md`](docs/architecture.md)，這裡只講一眼要記得的：

```
ui  →  games  →  core  →  data          net 由外部注入給 core，不被 import
```

**箭頭不可以反向。** 守住這一條，新增遊戲、換介面皮、換資料庫就永遠互不影響。

另一條同等重要的是資料面的：**答題事件是唯一的真相來源**。
金幣、經驗、星星、排行榜、老師報表全都是從事件算出來的，不各自獨立存。
「全班最常錯的字」就是對事件做一次 group by——所以之後要新報表不用改資料結構。

```
src/
  data/      題庫、十四關、三種佈局、塔的數值、商品。純資料，零邏輯。
  core/      quiz 出題／wordStat 掌握度／economy 金幣／progress 等級星星／
             inventory 背包／character 角色／session 一場遊戲
  games/     tower-defense。遊戲只吃關卡資料、只回報答題事件。
  net/       Repository 介面 ＋ localStorage 實作。之後換 Supabase 只改這裡。
  audio/     iOS 解鎖、靜音開關、缺檔時用 Web Audio 合成佔位音
  ui/        登入、選關、遊戲容器、結算、老師後台
```

### 遊戲的界線

**遊戲不算金幣、不算經驗、不算星星**，那是 `core` 的事。
一題值多少錢由字的難度與答過幾次決定，**跟你在玩哪個遊戲無關**——
遊戲唯一能影響的是「一分鐘能答幾題」，這樣加十個遊戲經濟都不會崩。

加一個新遊戲：在 `src/data/` 放資料、在 `src/games/<id>/` 實作 `GameModule`、
在 `src/games/index.ts` 註冊一行。core、經濟、資料庫、老師後台都不用動。

### 能力維度

「會這個字」是三件事：**認得出、拼得出、聽得懂**。
所以答題事件帶 `skill`（`recognize` / `spell` / `listen`），`wordStat` 分維度記。
守塔練的是 `recognize`；之後的拼字遊戲練 `spell`，兩者不互相抵消。

## 關卡

十四關，用完 300 字。**照主題切，不照年級**——課綱附錄五沒有年級分類，
但主題本身就帶難度（具體名詞 LV1 很多，抽象主題一個 LV1 都沒有），
所以由具體排到抽象，難度漸進自然成立。

關卡拆成三層：**外觀**（配色，每五關換一次）、**佈局**（路徑、高地、塔位，決定怎麼打）、
**規則**（波次、怪、魔王）。佈局才是玩法，外觀只是皮，而成本剛好顛倒。

目前三種佈局輪用（兩條路／一條長 S 形／三條同時湧入）。
十四關各有自己的佈局是目標，座標要一關一關調，還沒做完。

## 自動測試

```bash
npm run dev                                          # 另開一個終端機
node tools/test/play-td.mjs http://localhost:5173 1 1   # 關卡, 模擬正確率
```

機器人會自己蓋塔、開波、依題目點怪，回報每一波花多久、有沒有出題漏洞。
難度曲線要用這個驗，不要用手感猜。

## 資料庫

**還沒接。** 目前是 localStorage，但**存的是最終的事件形狀**，
之後換 Supabase 只是換掉 `src/net/index.ts` 那一行。

非接不可的時機有兩個：競爭／團隊模式（即時同步本地做不了），
以及第一次讓一整班真的玩之前（否則資料散在各平板，老師報表等於沒有）。

接上去之後**金幣和經驗不可以由客戶端直接寫**，要由資料庫函式從答題事件算出來。
班級代碼加暱稱不是真憑證，而小朋友真的會找漏洞。
