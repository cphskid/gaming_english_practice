# 載圖加速原則（2026-10-10 定）

Chuck：「進入關卡載圖速度超慢，都開始打了，地圖還沒展好……這個原則以後都要共用，重新產圖時都要考慮。」
樂園、守護異世界、島嶼開拓者都適用。

## 量出來的問題（2Mbps、延遲 150ms、不用快取）

| | 改之前（0.26.1） | 改之後（0.27.0） |
|---|---|---|
| 一進選關就抓的圖 | 154 張、1.84MB，全部到齊 12 秒 | 36 張、0.66MB，6 秒 |
| 點下去到地圖出來 | 2.0 秒，而且怪物圖還在後面排隊 | 沒預讀 1.0 秒（量的）；有預讀就直接從快取拿（推算） |
| 開打前圖沒到 | 照樣開打 | 不准開打，顯示「地圖還在載入」 |

原因：選關一出現就把 td-art.json 全部 150 張抓下來（五色像素城堡、雪地貼圖、軍團……），
第一章根本用不到，卻跟地圖、怪物搶頻寬。

## 七條原則

1. **每個畫面只抓自己用得到的圖。** 不要「一次全抓」；用 `loadArt(篩選)` 或畫面自己的清單。
2. **先出現的先抓。** 順序：底圖 → 城堡／塔位 → 第一波的怪 → 自己的英雄 → 其他（特效、別的職業）。
   art.ts 的 `PRIORITY` 就是這個順序。
3. **關鍵圖沒到不開打。** 地圖、城堡、怪物沒到，就顯示「載入中」、開戰鈕不給按；不要讓孩子在綠色空地上打。
4. **閒著就預讀。** 選關畫面先抓「該打的那一關」的地圖；點開關卡卡片的那一刻抓那一關（`prefetchMap`）。
5. **照畫面上的大小出圖，最多兩倍。** 角色畫在畫面上約 60px，動作條高 128px；英雄 150px；
   塔 240px 高；底圖 1360×720、webp 品質 74 左右、一張 ≤ 90KB；大地圖 ≤ 170KB；小圖示 ≤ 128px。
6. **重複的不要再存一份。** 同一組動作不要存兩個檔；上下翻的關卡用同一張圖翻過來畫。
7. **檔名固定、快取長存。** 換圖時沿用同一個網址會被舊快取卡住，要嘛升版號讓 Service Worker 換掉，要嘛換檔名。

## 產新圖時的檢查表

- 切圖腳本（art/guardian/cut2.py 這類）直接用上面的尺寸輸出，不要先存大圖再說。
- 新圖要放進「哪個畫面要抓」的清單（例：新畫風 p- 開頭由 `isParkKey` 涵蓋；程式畫地圖才用的放 `PARK_FALLBACK`）。
- 推上測試站前，用 tools/test 的載圖量測（2Mbps）確認：點下去到地圖出來 ≤ 1.5 秒、整個畫面的圖 ≤ 800KB。
