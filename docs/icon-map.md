# 圖示對照表：emoji → 像素圖

畫面上的圖示本來全是 emoji。emoji 在每支手機長得不一樣（iOS 的 🧊 跟 Android 的 🧊
是兩張圖），而且跟 Tiny Swords 的像素畫風格格不入。這份表是把它們換成
`assets/rpg-icons/`（7Soul1，CC0，34×34 像素畫）的對照結果。

**結論：道具系統本體全部配得到，裝飾品不該用圖示，只有星星和耳朵留著 emoji。**
（2026-09-21 已經做完並上線；城堡不用將就，Tiny Swords 本來就有一張。）

實際用到的十四張由 `tools/build-icons.py` 產生到 `public/icons/`，
鍵與檔名的對照就寫在那支的 `PICK` 裡。畫面上一律走 `src/ui/Icon.tsx`
（畫布外）或 `src/data/icons.ts` 的 `iconImg()`（引擎組 HTML 的地方），
散在各處各寫一次 `<img>` 遲早會漏掉一個。

## 零、道具在哪個模式有效

盤點的時候發現一件比圖示嚴重的事：**三個道具只有守塔實作了效果**。
`mountTugOfWar` 回傳的 GameHandle 沒有 `useItem`，但道具列是容器
（`GameHost`）畫的、每個遊戲都照樣長出來——所以在兵推裡按道具是**完全沒反應**：
沒訊息、沒效果、道具也不會被扣掉。

現在 `ItemDef.modes` 記著每個道具在哪些遊戲有效果，道具列照它過濾，
商店也標出來。三個道具兩邊都做了，但**效果不一樣**，因為兩個戰場不一樣：

| 道具 | 守塔 | 對戰 |
| --- | --- | --- |
| 寒霜陷阱 | 地面結霜 15 秒，怪剩三成速度 | 對方全軍凍住 8 秒（打得到的照樣還手） |
| 城牆修補 | 城堡回 5 點血（滿血 20） | 城堡回 15 點血（滿血 100） |
| 水晶補給 | +40 水晶，夠多蓋一座塔 | +40 水晶，夠升一階（升階是 30／80） |

守塔 15 秒在兵推砍成 8 秒，是因為守塔一波要打一分多鐘，兵推整場只有三分鐘。

回歸測試：`node tools/test/items-e2e.mjs`——每個道具在每個模式都驗
「按得到 → 真的被扣掉 → 效果量得到」三件事。

## 二、裝飾品那八格：不要用圖示

商店頁的陣營顏色用 🟥🟨🟪⬛、頭像外框用 🖼️🎗️👑🌈，但**「我的角色」那一頁早就做對了**：
顏色畫成色塊，外框直接套一張小頭像給你看。商店頁沿用同一套就好，不用另外找圖示。
一個外觀品項最好的縮圖就是它自己。

（順帶一提，這包裡**沒有皇冠也沒有彩虹**，硬配也配不到。）

## 四、尺寸

圖是 32×32（外面一圈透明邊共 34×34）。現在畫面上的 emoji 是 12~26px：
背包列 14px、HUD 15px、題目提示 26px。

在手機上（390×844、3 倍螢幕）一個 16px 的框其實是 48 個實體像素，所以 32px 的原圖
是**放大**到 48，不是縮小，不會糊。要更銳利就把框設成 32px，但 HUD 那一列會變高。
